# AGENTS.md

Discord bot (C#, .NET 10, Discord.Net 3.20) with virtual-money games, custom commands, reminders, and a local-LLM chat (Ollama). See [FILETREE.md](FILETREE.md) for a navigable file map — read it before searching.

## Solution layout (`DiscordBot/DiscordBot.sln`)
- `DiscordBot/` — main app (exe). Bot, commands, games, services, ASP.NET host.
- `Common/` — shared net10.0 lib: exceptions, helpers, Gist/local file storage. `Common/_nanogpt/` is unrelated Python (nanoGPT); ignore.
- `WebAlerter/` — Strawman trade checker (`StrawmanChecker`); its worker is currently disabled in `Startup.cs`.
- `Tests/` — xunit + Moq (`BlackjackTests`, `GPTHelperTests`, `WebAlerterTests`).

## Commands
```
dotnet build DiscordBot/DiscordBot.sln
dotnet test Tests/Tests.csproj
dotnet run --project DiscordBot
```
CI/CD: `azure-pipelines.yml` runs on the Pi itself (self-hosted pool `Pi`). It installs the .NET 10 SDK (`UseDotNet@2`), publishes linux-arm64 self-contained to a staging folder while the old bot keeps running, then stops the `DiscordBot` systemd service (`DiscordBot/DiscordBot.service`), backs up the files it is about to replace to `/srv/DiscordBot.prev`, copies the new build in and starts it. If the journal shows no Discord.Net `Gateway Ready` line within 5 minutes, or systemd restarts it, the old files are restored, the old bot restarted and the run fails. Save files (`coinaccounts.json`, `stockmarket.json`) are never touched, and live `mappings.json` / `reminders.json` are kept. Pushing to `master` deploys. Still build and test locally before pushing to `master`.

## Env vars (see `Common/Helpers/EnvironmentHelper.cs`)
`DiscordBotToken`, `GITHUB_PAT_TOKEN`, `GITHUB_USERNAME`, `GITHUB_GIST_ID`, `S_U`, `S_P`, `PORT` (default 5000), `IS_HEROKU`. Never commit secrets.
Gateway intents are set in `Startup.CreateDiscordConfig` (unprivileged + Message Content + Server Members; tested in `DiscordConfigTests`). Message Content and Server Members are privileged and are switched on in the Discord Developer Portal. To add another privileged intent (Presence), switch it on in the portal first, or Discord refuses the connection.
The dungeon deletes players' typed command messages to keep the channel clean. That needs the bot's **Manage Messages** permission in the server. Without it the commands stay, and the dashboard still works.

## Architecture
- Entry: `Program.cs` (Kestrel web host + generic host) → `Startup.cs` (**all DI registration**) → `ChatWorker` (hosted service; starts Ollama installer + `MessageHandler`).
- `MessageHandler` subscribes to Discord events and forwards messages to `CommandManager.RunCommand`, and buttons, select menus and modals (`ButtonExecuted`, `SelectMenuExecuted`, `ModalSubmitted`) to `RunComponent` / `RunModal` in `CommandManager_Components.cs`, run off the gateway task.
- Interactions: custom ids are `ComponentId.Build(game, action, args)` (`Models/ComponentId.cs`, "game:action:args", 100 chars max); the game prefix routes the click. Discord needs an answer within 3 seconds, so handlers acknowledge first (`DeferAsync()` when a dashboard edit is the answer, `DeferAsync(ephemeral: true)` for private views, or a modal as the very first response), and refusals go back privately (`FollowupAsync(..., ephemeral: true)`). The same gates as typed commands apply (stopped, banned, bots), and game clicks count as money activity for the raffle. Game dashboards are one message edited in place with `Services/LiveMessage.cs`: each frame's images get fresh file names (`Frame.Add` returns the `attachment://` url for the embed), and `BumpAsync` reposts at the bottom of the channel. Clicks on any older message are stale (`LiveMessage.Owns`).
- `CommandManager` is a **partial class** split across `Managers/CommandManager_*.cs`:
  - `_Main` — constructor, the `_commands` list, `RunCommand` parsing/dispatch.
  - `_Games` — roulette / blackjack / faceoff handlers.
  - `_Methods` — all other command handlers (largest file).
  - `_Bot` — bot-to-bot commands (`.initiatebet`, `.resolvebet`, `.lbjson`).
- Commands use prefix `.`; each is `Command(name, handler)` with `Description`, `Syntax`, `Hidden`, `RequiresAdmin`. Handler signature: `Task X(DiscordSocketClient, SocketMessage, List<string> args)`.
- Games: `Games/<Game>.cs` (rules) + `Games/Managers/<Game>Manager.cs` (session/lobby, derives `BaseMultiplayerManager`) + `Games/Models/` (players, cards, bets).
- Feature flag: `AppSettings.PrestigeDisabled` (appsettings.json, default `true`) disables `.prestige`, prestige scaling of interest/daily income/bonus threshold. Interest is `Constants.InterestPercentage` (2%).
- Dungeon (`.dng`): rules in `Games/Models/Dungeon/DungeonSession.cs` (pure, clock and Random injected) and `DungeonRun.cs`; `Games/Managers/DungeonManager.cs` takes and pays money, ticks the session every 1.5 s (each tick moves every crawling run one floor, which animates the dashboard) and publishes the dashboard with buttons. Runs stop at each boss door (floors 5 and 10) to fight, sneak (`DungeonRun.SneakChance` 50%, otherwise the boss strikes first enraged) or drink a potion and fight; a door left 60 s is fought. Potions drop in chests (25%) and quiet corridors (10%) and heal 50% of max HP. Block odds stay about 50/25/12.5% with plain fighting (`DungeonOddsTests`; tune `BlockDifficultyStep` and `MonsterFor`). Typed `.dng` subcommands still work and refusals are posted briefly; button refusals are private.
- Face Off (`.fo`): rules in `Games/BattleArena.cs`, side bets in `Games/Models/BattleArena/SpectatorPool.cs`, Discord flow in `Games/Managers/BattleArenaManager.cs` (one `LiveMessage` dashboard per fight, a gate, and a 1 s timer loop). It reuses the base manager's `Games` list, `BetManager.InitiateBet`/`CancelBet` escrow and `EndGame` results, but not its message-based `Start`/`CreateOrJoin`. Up to 6 fighters; the lobby starts 60 s after the second joins, and a lone lobby is refunded after 5 minutes. Each round picks are private (buttons, ephemeral confirmations; typed picks are deleted where the bot can), revealed together, 30 s per round, and a player who doesn't pick attacks a random opponent. Attack and Gamble hit one chosen target (a private select menu with 3+ fighters). A natural 20 is always the best roll, damage is whole numbers, and after `BattleArena.MaxRounds` (12) the highest HP wins; ties and players who go down together split the pot (`BattleArena.Winners`). Spectators back a fighter (select menu, then an amount modal) until round 1 resolves; backers of the winner share the whole backing pool by stake, or everyone is refunded if nobody backed a winner.
- First gamble of the day (`BetManager.ResolveBet`, tracked by `CoinAccount.LastGambleDate`): d10 roll, a 10 steals 10% of the cash of whoever is 1st on the leaderboard (cash + stocks), unless the roller is already 1st; result is read via `BetManager.TakeDailyRoll`.
- Stocks: `Services/StockService` (singleton) ticks every 5-min UTC slot from the `ChatWorker` minute loop via `CommandManager.RunBackgroundTasks`; risk tiers/swings in `Models/Stock.cs`; `.stocks .buy .sell .portfolio`. Leaderboard ranks cash + stock value. Trades move the quoted price (`Stock.Price` = `FairPrice` × (1 + `Impact`)): impact grows with the square root of the shares traded against the stock's `SharesOutstanding`, fills at the midpoint of before and after plus a fixed 1% spread (buys pay half above, sells receive half below), and impact fades by half each tick. Sells pay a 2% tax on gross value (`Stock.SellTaxRate`) that goes into the jackpot, so churning costs. Tiers 3-6 each hold one random stock (tier 6 is crypto with moon/crash bursts and a strong rebound after a crash), picked at random from `StockMarket.Pool` whenever the market is created (`.clear coin`). `.stocks` graphs are green or red by `Stock.AllTimeChange` and take a window like `48h` (`DurationParser`). `.short`/`.cover` lock margin (closed at 2x entry); `.call`/`.put` are cash-settled at-the-money options on the fair price (100 shares each, settled in `StockService.TickIfDue`). Shorts and options count in `GetPortfolioValue` and block the jackpot via `HasPositions`.
- Raffle: `Services/RaffleService` draws every hourly UTC slot (`SlotMinutes`, from `CommandManager.RunBackgroundTasks`; a larger saved `LastRaffleSlot` from the old 30-minute schedule is reset). Anyone whose last money command (`_moneyCommands` in `CommandManager_Main.cs`, stamped by `CoinService.MarkActive`) was within `EntryWindow` (1h) before the draw's due time (`IsEnteredIn`) is entered; `ActiveWindow` (24h) is only the pool for attacks and sharing. The winner's power-up from `PowerUpCatalog` (`Models/PowerUp.cs`, 36 of them) goes off straight away (`RaffleService.Activate`, which runs `ApplyUse`; a Copycat's copy goes off too). One that can't go off yet (`BadInputException`, or the winner has a bet open) is kept for 24h for `.pu use N`. The result is announced in one line (named, not pinged) in the channel of the last money command. `.pu list` shows the catalog. The draw rubber-bands (`PowerUpCatalog.WeightFor` with a `PickContext` from `RaffleService.ContextFor`): each power-up has a `PowerUpCategory`; the top tier (`TopTier`: 3, at most half the board) only draws Boosts, lower players draw Attacks and CatchUp more the lower they are, and CatchUp is 3x when 1st is worth over `RunawayMultiple` (3x) the median active player. Attacks go through `RaffleService.Hit` (Shield refuses them before; Mirror reflects; Golden Parachute cancels the debt part), then `Seize` (cash first, the rest on the victim's debt). CatchUp items (Tax the Rich, Audit, Bailout, Squatters, Leech) skip Shield/Mirror/Parachute and are refused for the top tier. Debuffs (`audited`, `frozen`, `squatted`, `leeched`, `PowerUpCatalog.Debuffs`) sit on the victim's `ActivePowerUps`, with `BeneficiaryUserId` for squat/leech. Hooks: `BetManager.ResolveBet` (`BetBonus`, `PowerUps.SettleWin` skims for Audit/Leech/Toll Booth, records the last loss for Time Machine), `CoinService.AddInterest` (Compound Interest, no interest while audited), `PropertyService.PayRentOneHour` (a squat is on one property, `ActivePowerUp.PropertyId`, the leader's best unsquatted rental; old saves without one squat the first property), `StockService.Buy/Sell`, the daily steal (Loaded Dice), `Draw` (Rigged Raffle) and `ApplyUse` (Freeze, Echo, `CoinAccounts.LastUsedPowerUpId` for Copycat). Numbers are constants in `PowerUpCatalog`.
- Property: `Services/PropertyService` + `Models/Property.cs`. Houses and apartments bought with cash only (`.buyproperty`, `.sellproperty`, `.property`). Prices follow one shared index on `CoinAccounts` (stepped once a UTC day, booms and busts, clamped 0.6–1.6). Buying costs 4.5% stamp duty, selling costs 3%. Every property is always rented out (there is no on/off; old saves' `LetOut` flag is ignored). Rent is paid hourly after an 8% agency fee and 4% vacancy: 3.5% of the current market price per hour for houses and 4% for apartments (`PropertyCatalog.HouseGrossYieldPerHour`) (`PropertyCatalog.RentPerHour`, `PropertyService.PayRentOneHour`). Prices update once a UTC day, and rent follows them. Holding costs (1.5% of value a year) are charged daily (`PayHoldingOneDay`). Property counts in net worth at its after-selling-costs value (`CoinService.PropertyValue`) and blocks the jackpot, like stocks. Constants are in `PropertyCatalog`. Debt: `CoinAccount.Debt` is counted against net worth and grows 1% a day, compounded hourly in `CoinService.AddInterest`. Blue Shell and Pickpocket take a share of the victim's net worth: their cash first (`RaffleService.Seize`), and any shortfall goes on their debt. Stock and property sale proceeds pay debt first (`CoinAccount.PayDebtFrom`), and any spare cash pays debt automatically every minute (`CoinService.RepayDebtsFromCash`, skipping players with a bet open). Players with `CoinAccount.AutoSellForDebt` on (`.autosell on`) then have assets sold for what's left (`Services/DebtService`, planned by `DebtService.Plan`: stocks first, the biggest holding first and only as many shares as needed; then the cheapest property that covers the rest, else the most valuable; shorts and options are left alone).
- Market crashes: `Models/MarketCycle.cs`. Roughly once every 2 years (`MarketCycle.DailyChance`, rolled once a UTC day in `PropertyService.TickIfDue`), a crash runs Decline (14 days), Bottom (5) and Recovery (120). Ordinary stocks fall 26–50% by tier (crypto 60%) and property falls 25% over the decline; `StockService.TickIfDue` applies the drift each tick via `MarketCycle.DriftFor`, with mean reversion off. Once the crash ends, stocks keep their new level as their base (`ResetBasePrices`). Headlines are posted to the last active channel. Phase state lives on `CoinAccounts` (`MarketPhase`, `NextCrisisAllowedDay`).
- Tiers 1 and 2 hold only safe havens: `BOND` is tier 1 and `GOLD` is tier 2. Old markets that still had an ordinary stock there are migrated on load (`StockMarket.SchemaVersion`, `StockMarket.Retire` pays holders out at current value).
- Safe havens: `GOLD` rises 20% during a decline and fades back to its base after; `BOND` pays about 0.02% a day with almost no swing. Both are always listed (`StockMarket.SafeHavens`, `Stock.Role`), not drawn from the random pool, and trade with `.buy`/`.sell`.
- Money: `Services/CoinService` (accounts, interest, leaderboard) + `Managers/BetManager` (initiate/resolve bets, bonuses, stats). Jackpot: sell tax and the 20% donation tax go into `CoinAccounts.JackpotPool`. When a `max` bet covers all cash with no stocks or property held, `BetManager.ResolveBet` rolls `JackpotWinChance` (3%) to pay the pool out. Persistence via `Common/Services` (`GistService` remote, `LocalFileService` local).

## Adding things
- **New command**: write handler in the matching `CommandManager_*.cs`, then register it in the `_commands` list in `CommandManager_Main.cs` (comment there says so).
- **New service**: create in `DiscordBot/Services/`, register in `Startup.ConfigureServices`, inject into `CommandManager` ctor if commands need it.
- **New game**: Game + Manager + Player model, register Manager singleton in `Startup`, add handler in `CommandManager_Games.cs`.

## Conventions / gotchas
- Files use UTF-8 BOM and namespaces matching folders (note: `DiscordBot.Exceptions` namespace is used for exceptions that live in `Common/Exceptions`).
- Hardcoded admin/bot IDs live in `CommandManager_Main.cs` (`_adminIds`, `_botId`); blacklists in `appsettings.json` (`AppSettings.cs`).
- Discord message limit 2000 chars (`_messageCharLimit`); keep replies under it. Embeds are capped at 6000 chars total and 1024 per field, so long lists go through `TextPaginator.Paginate` (`Common/Helpers/TextPaginator.cs`) and send one embed per message, as `.help` does.
- `mappings.json` / `reminders.json` are runtime data copied to output.
- Patch notes: a significant change gets a one-line entry at the top of `PatchNotes.All` (`Models/PatchNotes.cs`); `.patchnotes` shows them.
- Branch `gambling-rework` is active; `master` is the deploy branch.
