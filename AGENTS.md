# AGENTS.md

Discord bot (C#, .NET 10, Discord.Net 3.20) with virtual-money games, custom commands, reminders, and a local-LLM chat (Ollama). See [FILETREE.md](FILETREE.md) for a navigable file map — read it before searching.

## Solution layout (`DiscordBot/DiscordBot.sln`)
- `DiscordBot/` — main app (exe). Bot, commands, games, services, ASP.NET host.
- `Common/` — shared net10.0 lib: exceptions, helpers, Gist/local file storage. `Common/_nanogpt/` is unrelated Python (nanoGPT); ignore.
- `WebAlerter/` — Strawman trade checker (`StrawmanChecker`); its worker is currently disabled in `Startup.cs`.
- `Tests/` — xunit + Moq (`BlackjackTests`, `GPTHelperTests`, `WebAlerterTests`).

## Commands
```
dotnet build DiscordBot/DiscordBot.sln
dotnet test Tests/Tests.csproj
dotnet run --project DiscordBot
```
CI/CD: `azure-pipelines.yml` runs on the Pi itself (self-hosted pool `Pi`). It installs the .NET 10 SDK (`UseDotNet@2`), publishes linux-arm64 self-contained to a staging folder while the old bot keeps running, then stops the `DiscordBot` systemd service (`DiscordBot/DiscordBot.service`), backs up the files it is about to replace to `/srv/DiscordBot.prev`, copies the new build in and starts it. If the journal shows no Discord.Net `Gateway Ready` line within 5 minutes, or systemd restarts it, the old files are restored, the old bot restarted and the run fails. Save files (`coinaccounts.json`, `stockmarket.json`) are never touched, and live `mappings.json` / `reminders.json` are kept. Pushing to `master` deploys. Still build and test locally before pushing to `master`.

## Env vars (see `Common/Helpers/EnvironmentHelper.cs`)
`DiscordBotToken`, `GITHUB_PAT_TOKEN`, `GITHUB_USERNAME`, `GITHUB_GIST_ID`, `S_U`, `S_P`, `PORT` (default 5000), `IS_HEROKU`. Never commit secrets.
Gateway intents are set in `Startup.CreateDiscordConfig` (unprivileged + Message Content + Server Members; tested in `DiscordConfigTests`). Message Content and Server Members are privileged and are switched on in the Discord Developer Portal. To add another privileged intent (Presence), switch it on in the portal first, or Discord refuses the connection.
The dungeon deletes players' typed command messages to keep the channel clean. That needs the bot's **Manage Messages** permission in the server. Without it the commands stay, and the dashboard still works.

## Architecture
- Entry: `Program.cs` (Kestrel web host + generic host) → `Startup.cs` (**all DI registration**) → `ChatWorker` (hosted service; starts Ollama installer + `MessageHandler`).
- `MessageHandler` subscribes to Discord events and forwards messages to `CommandManager.RunCommand` (synchronously on the gateway task, so a command that never finishes stops the heartbeats and takes the bot offline; `Services/HangWatchdog` then fails fast after 10 minutes offline or with the minute loop stuck, and systemd restarts it), and buttons, select menus and modals (`ButtonExecuted`, `SelectMenuExecuted`, `ModalSubmitted`) to `RunComponent` / `RunModal` in `CommandManager_Components.cs`, run off the gateway task.
- Interactions: custom ids are `ComponentId.Build(game, action, args)` (`Models/ComponentId.cs`, "game:action:args", 100 chars max); the game prefix routes the click. Discord needs an answer within 3 seconds, so handlers acknowledge first (`DeferAsync()` when a dashboard edit is the answer, `DeferAsync(ephemeral: true)` for private views, or a modal as the very first response), and refusals go back privately (`FollowupAsync(..., ephemeral: true)`). The same gates as typed commands apply (stopped, banned, bots), and game clicks count as money activity for the raffle. Game dashboards are one message edited in place with `Services/LiveMessage.cs`: each frame's images get fresh file names (`Frame.Add` returns the `attachment://` url for the embed), and `BumpAsync` reposts at the bottom of the channel. Clicks on any older message are stale (`LiveMessage.Owns`).
- Crash (`.crash 1000 [2x]`): rules in `Games/CrashGame.cs` (pure), flow in `Games/Managers/CrashManager.cs`, command and buttons (`crash:out`, `crash:again`) in `CommandManager_Crash.cs`. The multiplier is e^(`GrowthPerSecond` x seconds); the crash point is drawn so P(reaching m) = (1 - `HouseEdge`)/m, so every cash-out target pays back 97% on average and 3% blow up on the pad; it tops out at `MaxMultiplier` (100x). The stake goes through `BetManager` (daily roll, jackpot, stats, 75% of losses to the jackpot). A round's message is edited every `TickEvery`; `CrashManager.CashedAt` decides the result from the clock (an auto target the rocket reached pays the target even if the loop noticed late). `CrashGameTests` simulate the payback.
- Slots (`.slots`, `.slot`): rules in `Games/SlotMachine.cs` (three weighted 30-stop reels, line pays by a table; `ReturnToPlayer()` is worked out exactly and tested to stay at 90-96%; three 💎 pay the pool, at least x100 and at most x2000 the bet), text and buttons in `Games/SlotView.cs`, money and animation in `Games/Managers/SlotMachineManager.cs`, handlers in `Managers/CommandManager_Slots.cs`. One machine message per player, owner-only buttons (`slot` prefix: Spin, Bet ½, Bet x2, Max, Bet…, Cash out) and the session lives in memory (30 minutes idle). A spin settles the bet through `BetManager` first and only then shows the result with one instant edit of the message (no spinning frames), so a failed edit can't lose money. Typed `.slots` is deleted after the machine is posted.
- Stats (`.stats [me|@user] [page]`): `Services/StatsReport.cs` builds nine pages (overview, betting, games, stocks, property and debt, jackpot and income, power-ups, dungeon, donations) from `CoinAccountStats` plus a `StatsContext` the command fills in (`CommandManager.StatsEmbed`), with a `stats:pick:<accountId>` select menu that edits the message (public, anyone can switch pages). The counters are updated where the money moves: `BetManager.ResolveBet` (per-game `GameRecord`s keyed by the `game` argument, daily roll, jackpot, bonus, jackpot feed), `StockService` trades and option settlement, `PropertyService` buy/sell/rent/holding costs, `RaffleService` (draws, uses, `Seize`/`Hit`), `CoinService.AddInterest`, `CoinAccounts.PayDebtFrom/RepayFromCash`, `DungeonManager`. New counters start at zero on old accounts. Add a counter by adding a property to `CoinAccountStats`, updating it at the hook and showing it in `StatsReport`.
- Money buttons (`Managers/CommandManager_MoneyButtons.cs`, prefixes in `Models/MoneyComponents.cs`: `stk`, `pu`, `prop`, `debt`, `slot`; blackjack and duck race use their base command, `bj`/`duck`): Buy/Sell on `.stocks` (a pick menu), `.stocks SYMBOL` and trade results; Sell menus and the auto-sell switch on your own `.portfolio`; Use buttons on `.pu` and a My power-ups button on raffle results; Buy a house on `.property`; Join…/Join max (`joinmax`: all your cash, no form)/Start on game lobbies, Play again… on duck race results (opens the bet form), Hit/Stay in blackjack, and on blackjack results Play again (`bj:again`: `BlackjackManager.PlayAgainBet`, the same share of the clicker's cash as their last bet (`BasePlayer.BetShare`, set when they joined; kept in memory by the base manager), raised to the 10% minimum and held to their cash, then create and start at once; with no last bet it opens the form) and New bet…. They call the same methods as typed commands (`BuyStockText`, `SellStockText`, `BuyPropertyText`, `UsePowerUpText`, `AutoSellText`), so rules and wording match, and results post publicly. Buttons on shared things act for whoever clicks; buttons on someone's own view carry their id and only work for them (`ButtonOwner`). Amounts come from `AmountModal`. Houses are sold by `PropertyHolding.Id` (`PropertyService.SellById`) and kept power-ups found with `PowerUps.FindHeld`, so a list that moved can't hit the wrong one.
- `CommandManager` is a **partial class** split across `Managers/CommandManager_*.cs`, one file per feature:
  - `_Main`: constructor, the `_commands` list, `RunCommand` parsing/dispatch, the minute loop (`RunBackgroundTasks`, each step wrapped in `Safely` so one failure never stops the rest) and reminders.
  - `_Games`: roulette, blackjack, duck race and dungeon handlers, and `TryExtractBetAmount`. `_Slots`, `_Crash`, `_Raids` (raids and the `.card` panel), `_Cards` (`.cardpull`), `_Bets` (calls and puts).
  - `_Stocks`, `_Property`, `_Economy` (leaderboard, net worth, donate, jackpot, stats), `_PowerUps`, `_Fun` (roll, time, images, lang, convo), `_Admin`, `_Utility` (custom commands, reminders, help, patch notes).
  - `_Components` and `_MoneyButtons`: button, menu and modal routing.
  - `_Bot`: bot-to-bot commands (`.initiatebet`, `.resolvebet`, `.lbjson`).
- Code review: `.claude/agents/code-reviewer.md` is a read-only reviewer agent with this repo's checklist (money rules, escrow, threads, saves, text matching code, Discord limits). Run it on a change before pushing to `master`.
- Commands use prefix `.`; each is `Command(name, handler)` with `Description`, `Syntax`, `Hidden`, `RequiresAdmin`. Handler signature: `Task X(DiscordSocketClient, SocketMessage, List<string> args)`.
- Lobbies (blackjack, duck race) are shared: there is one open lobby for everyone, across channels and servers (`CreateOrJoinLocked` joins the first game that hasn't started, and results and start messages go to every player's channel), and someone has to press Start or type `.bj start`. That is intentional (see "Intentional behaviour" below). The force-end timer logs failures instead of losing them.
- Games: `Games/<Game>.cs` (rules) + `Games/Managers/<Game>Manager.cs` (session/lobby, derives `BaseMultiplayerManager`) + `Games/Models/` (players, cards, bets). The base manager takes a `GameContext` (user, channel, guild; `GameContext.From` a message or an interaction) rather than a message, and runs every change under one lock (`Locked`), since typed commands and button clicks run on different threads. A game's messages go through `AnnounceLobby`, `AnnounceStart` and `AnnounceResults` (the defaults post a message each time, as duck race does). A game with a slow animation sets `AnimateInBackground` (duck race, a replay of seconds): `Start` returns at once and `AnimateAndContinueAsync` replays it without the lock, then takes the lock to pay out, so the gateway and the other commands are never held (`DuckRaceBackgroundTests`). Blackjack overrides them to keep one table message per channel (`BlackjackManager.Publish`, text in `Games/BlackjackView.cs`) edited from the lobby through the hands (Hit/Stay) to the results, and deletes typed `.bj` commands where it can.
- Feature flag: `AppSettings.PrestigeDisabled` (appsettings.json, default `true`) disables `.prestige`, prestige scaling of interest/daily income/bonus threshold. Interest is `Constants.InterestPercentage` (2%).
- Dungeon (`.dng`): rules in `Games/Models/Dungeon/DungeonSession.cs` (pure, clock and Random injected) and `DungeonRun.cs`; `Games/Managers/DungeonManager.cs` takes and pays money, ticks the session every 1.5 s (each tick moves every crawling run one floor, which animates the dashboard) and publishes the dashboard with buttons. Runs stop at each boss door (floors 5 and 10) to fight, sneak (`DungeonRun.SneakChance` 50%, otherwise the boss strikes first enraged) or drink a potion and fight; a door left 60 s is fought. Potions drop in chests (25%) and quiet corridors (10%) and heal 50% of max HP. Block odds stay about 50/25/12.5% with plain fighting (`DungeonOddsTests`; tune `BlockDifficultyStep` and `MonsterFor`). Typed `.dng` subcommands still work and refusals are posted briefly; button refusals are private.
- First gamble of the day (`BetManager.ResolveBet`, tracked by `CoinAccount.LastGambleDate`): d10 roll, a 10 steals 10% of the cash of whoever is 1st on the leaderboard (cash + stocks), unless the roller is already 1st; result is read via `BetManager.TakeDailyRoll`.
- Stocks: `Services/StockService` (singleton) ticks every 5-min UTC slot from the `ChatWorker` minute loop via `CommandManager.RunBackgroundTasks`; risk tiers/swings in `Models/Stock.cs`; `.stocks .buy .sell .portfolio`. Amounts can be a share (`.buy SYMBOL 50%`, `StockService.TryParsePercent`, 0-100%): of cash for buy, short and options (`MaxAffordableContracts(..., cashShare)`), of the holding for sell and cover (rounded down, under one share is refused). Leaderboard ranks cash + stock value. Trades move the quoted price (`Stock.Price` = `FairPrice` × (1 + `Impact`)): impact grows with the square root of the shares traded against the stock's `SharesOutstanding`, fills at the midpoint of before and after plus a fixed 1% spread (buys pay half above, sells receive half below), and impact fades by half each tick. Sells pay a 2% tax on gross value (`Stock.SellTaxRate`) that goes into the jackpot, so churning costs. Tiers 3-6 each hold one random stock (tier 6 is crypto with moon/crash bursts, equally likely and equally big in log terms (`CryptoMoonChance` = `CryptoCrashChance`, steps `CryptoStepMin`..`CryptoStepMax`), and a strong rebound after a crash; keep them balanced), plus rare **mega events** (`CryptoMegaChance`, about one boom and one crash every 2 days each way, `MegaTicks`/`MegaStep`): a log move of at least ln 10 plus an exponential tail up to ln 100,000 (`Stock.MegaSize`: every event is 10x or more, 1 in 10 reaches 100x, 1 in 100 reaches 1,000x, none passes 100,000x), spread over 2 to 6 ticks, then fading back at the normal 3% pull with no special rebound. There is no cap on a boom beyond that, so a season's crypto high is typically hundreds of times its launch price and its low a few tenths of a percent. Crypto's floor is `CryptoMinPrice` (1 cent; others keep $1), prices under a dollar are kept to 4 decimals (`Stock.RoundPrice`, shown with `Stock.FormatPrice`), and its trading impact is uncapped on buys and capped at a 95% drop on sells, filled at the average along the impact curve (`PreviewCryptoTrade`), so a huge order pays for its own impact. Holding crypto therefore has a large positive average return (mean reversion plus rare giant booms); it is not a fair bet, and `OptionPricingTests` only guarantee that its options are priced fairly. Options on crypto are expensive (a 6 hour call costs about 90% of the price) and capped at 20x their strike, picked at random from `StockMarket.Pool` whenever the market is created (`.clear coin`). `.stocks` graphs are green or red by `Stock.AllTimeChange` and take a window like `48h` (`DurationParser`). `.short` is retired (it points at puts); `.cover` still closes old shorts, which lock margin and are closed at 2x entry. `.call`/`.put` are **leveraged bets** (`Models/LeveragedBet.cs`, commands in `CommandManager_Bets.cs`): `.call SYMBOL amount [2x|5x|10x] [15m..24h]` (default 5x for 1h; no amount shows the payout table for $1,000). Of what you pay, `Stake` rides and the rest is the fee (into the jackpot); at close it pays `Stake x (1 + leverage x move)` on the fair price, never below 0 and at most `LeverageRules.MaxMultiple` (10x) the stake. Only the closing price counts: a mid-bet dip doesn't wipe you out (a knock-out version was tried and paid back about 16% on average because prices revert to their base). The fee comes from `LeveragePricer`, which runs the real `Stock.ApplyTick` forward from the stock's state (fair vs base, crypto streak, crash drift) and averages the payout, so every bet pays back `HouseReturn` (95%) of what's paid on average (at least `MinFeeShare` 2%; refused when the fee would pass `MaxFeeShare` 80%). Some bets are worse than 95% even at the minimum fee (betting against a stock that's likely to bounce); the payout table then warns with the average payback (`PoorPayback`). The table also shows the wipe-out price, break-even (after the fee), a few outcomes and the max. Bets settle in `StockService.TickIfDue` (`SettleBets`, debt paid first) and are announced in the channel they were made in (`AnnounceSettledBets`); debt auto-sell can close them early at current value (`CloseBetForDebt`). Old-style options (`OptionContract`) are no longer sold but still settle. `LeveragedBetTests` checks the payout maths, that the house keeps its edge against an independent simulation and that quotes match it; re-run them after changing tick dynamics (`ApplyTick`, reversion, crypto bursts). Shorts, bets and old options count in `GetPortfolioValue` and block the jackpot via `HasPositions`. Share counts are `int`: `MaxAffordableShares`/`MaxShortableShares` search in `long` (an int search overflowed with billions of cash and looped forever inside the stock lock), and a holding or short can't pass `int.MaxValue` (`StockMarket.TooManyShares`).
- Live stock thread (`.stocksthread`, `.stocksthread stop`, bot admins only via `RequiresAdmin`): `Services/StockThreadService` opens a public thread (one per server) with ONE live message (`LiveStockThread.BoardMessageId`): an embed with a line per stock (price, 5 minute, 3 hour and all-time change, in `.stocks` order via `StockTickerCard.Ordered`) and one image from `StockTickerCard.BuildBoard`: a row per ordinary stock with its all-time chart on the left and the last 3 hours (`StockThreadService.RecentWindow`) on the right, both as % change like `.stocks` (gold and bonds are in the text only; each panel is green or red by its own change). `RunBackgroundTasks` starts `RefreshIfDue` without awaiting it; after each new stock tick it edits the board in place with a fresh image (the file name carries the tick, so clients don't cache), unarchives the thread if needed, and reposts it if it was deleted. Threads saved before the board (a header plus a message per stock: `HeaderMessageId`, `Tickers`, `LiveStockThread.IsOldLayout`) have those messages deleted and the board posted on their next refresh. Thread and message ids are saved in `stockthreads.json` (`Models/StockThread.cs`), so updates survive deploys. Stopping or moving a thread deletes it (`DeleteQuietly`; without Manage Threads it deletes the bot's messages and archives it). `StockThreads.CleanupVersion` below `CurrentCleanupVersion` makes the next refresh delete every ticker thread the bot owns in every server, open or archived, once. `Services/StockTickerCard.cs` also builds the single-stock card for `.stocks SYMBOL`.
- Raffle: `Services/RaffleService` draws every hourly UTC slot (`SlotMinutes`, from `CommandManager.RunBackgroundTasks`; a larger saved `LastRaffleSlot` from the old 30-minute schedule is reset). Anyone whose last money command (`_moneyCommands` in `CommandManager_Main.cs`, stamped by `CoinService.MarkActive`) was within `EntryWindow` (6h) before the draw's due time (`IsEnteredIn`) is entered, so one action covers the next 6 draws (`EnteredDrawCount`, shown in `.pu`); `ActiveWindow` (24h) is only the pool for attacks and sharing. The winner's power-up from `PowerUpCatalog` (`Models/PowerUp.cs`, 36 of them) goes off straight away (`RaffleService.Activate`, which runs `ApplyUse`; a Copycat's copy goes off too). One that can't go off yet (`BadInputException`, or the winner has a bet open) is kept for 24h, and `RaffleService.ActivateKept` (every minute from `RunBackgroundTasks`, `ActivateKeptAndAnnounce`) tries every kept power-up and sets it off the moment it can (skipping players with a bet open or frozen; each is announced in the last active channel), so `.pu use N` is only a way to try one now. The result is announced in one line (named, not pinged) in the channel of the last money command; if that channel can't be reached or written to, `RaffleService.Announce` tries the other recent channels, and a message no channel takes waits in `AnnouncementQueue` and is retried every minute for 30 minutes (in memory), so a winner isn't lost. `.pu list` shows the catalog. The draw rubber-bands (`PowerUpCatalog.WeightFor` with a `PickContext` from `RaffleService.ContextFor`): each power-up has a `PowerUpCategory`; the top tier (`TopTier`: 3, at most half the board) only draws Boosts, lower players draw Attacks and CatchUp more the lower they are, and CatchUp is 3x when 1st is worth over `RunawayMultiple` (3x) the median active player. Attacks go through `RaffleService.Hit` (Shield refuses them before; Mirror reflects; Golden Parachute cancels the debt part), then `Seize` (cash first, the rest on the victim's debt). CatchUp items (Tax the Rich, Audit, Bailout, Squatters, Leech) skip Shield/Mirror/Parachute and are refused for the top tier. Debuffs (`audited`, `frozen`, `squatted`, `leeched`, `PowerUpCatalog.Debuffs`) sit on the victim's `ActivePowerUps`, with `BeneficiaryUserId` for squat/leech. Hooks: `BetManager.ResolveBet` (`BetBonus`, `PowerUps.SettleWin` skims for Audit/Leech/Toll Booth, records the last loss for Time Machine), `CoinService.AddInterest` (Compound Interest, no interest while audited), `PropertyService.PayRentOneHour` (Squatters moves into every property the leader owns that has no squat yet except their `PowerUpCatalog.SquattersSpared` (2) cheapest rentals, but always at least one (the best rental when they own 1 to 3), one `Squatted` debuff per property with `ActivePowerUp.PropertyId`; refused when every property it can reach is taken; old saves without a property id squat the first one); a squatted property can't be sold while the squat runs (`PropertyService.SquatIn`, checked in `Sell`, so `.sellproperty`, the sell button and `DebtService` auto-sell, which leaves it out of its plan, all respect it), or selling and rebuying would shake the squatters off, `StockService.Buy/Sell`, the daily steal (Loaded Dice), `Draw` (Rigged Raffle) and `ApplyUse` (Freeze, Echo, `CoinAccounts.LastUsedPowerUpId` for Copycat). Numbers are constants in `PowerUpCatalog`.
- Property: `Services/PropertyService` + `Models/Property.cs`. Houses only, bought with cash (`.buy property`, `.sell property N` or `.sell property all` (`PropertyService.SellAll`: every house but any with squatters in), `.property`; `BuyStock`/`SellStock` hand "property" and "house" to `BuyProperty`/`SellProperty`, and the old one-word `.buyproperty`/`.sellproperty` stay as hidden aliases). Apartments were removed: `PropertyKind.Apartment` stays only so old saves load, and `PropertyService.BuyBackApartments` (each `TickIfDue`) pays any left at full market price. Prices follow one shared index on `CoinAccounts` (stepped once a UTC day; booms and busts last 4 to 8 days at about 2% a day, `PropertyCatalog.TrendPerDay`/`MinTrendDays`, so they show within a season; no ceiling and no ordinary floor, only `PropertyCatalog.IndexFloor` (0.01) so a price never reaches zero; each day also has a fat-tailed random move, `PropertyMarket.Laplace` at `NoisePerDay`, or `ShockScale` on a 4% `ShockChance` day, so a day can move houses 10% to 30% or more either way; a trend saved with a longer length is cut by `PropertyMarket.CutOldTrend`). Buying costs 4.5% stamp duty, selling costs 3%. Every property is always rented out (there is no on/off; old saves' `LetOut` flag is ignored). Rent is paid hourly after an 8% agency fee and 4% vacancy: 0.7% of the current market price per hour (`PropertyCatalog.HouseGrossYieldPerHour`; it was 3.5%, which paid a house back 6x its price in two weeks) (`PropertyCatalog.RentPerHour`, `PropertyCatalog.NetRentPerHour` after the fee, `PropertyService.PayRentOneHour`; `.portfolio` shows the hourly total, less any squatted property). Prices update once a UTC day, and rent follows them. Holding costs (0.3% of the current value an hour, `PropertyCatalog.HoldingCostPerHour`) are charged with the rent each hour (`PayHoldingOneHour`). Property counts in net worth at its after-selling-costs value (`CoinService.PropertyValue`) and blocks the jackpot, like stocks. Constants are in `PropertyCatalog`. Debt: `CoinAccount.Debt` is counted against net worth and grows 10% every hour (`CoinAccount.HourlyDebtInterest`, in `CoinService.AddInterest`). Blue Shell and Pickpocket take a share of the victim's net worth: their cash first (`RaffleService.Seize`), and any shortfall goes on their debt. Stock and property sale proceeds pay debt first (`CoinAccount.PayDebtFrom`), and any spare cash pays debt automatically every minute (`CoinService.RepayDebtsFromCash`, skipping players with a bet open). Players with `CoinAccount.AutoSellForDebt` on (`.autosell on`) then have assets sold for what's left (`Services/DebtService`, planned by `DebtService.Plan`: stocks first (gold and bonds included), the biggest holding first and only as many shares as needed; then shorts the same way (`StockService.Cover`, the most equity first); then calls and puts worth something, closed at what they'd pay now (`StockService.CloseBetForDebt`), and old options less the 2% option fee (`StockService.CloseOption`; worthless ones are left alone); then the cheapest property that covers the rest, else the most valuable; cover and option cash goes straight on the debt with `RepayFromCash`). Selling moves the price, so one plan can fall short: `AutoSellForDebts` plans and sells again from the new prices (`SellRound`, up to `DebtService.MaxRounds`) until the debt is zero or nothing sellable is left.
- Market crashes (the GFC): `Models/MarketCycle.cs`. The daily roll (once a UTC day while the market is normal, in `PropertyService.TickIfDue`) is `MarketCycle.ChanceFor(exposure)`: `DailyChance` (1/20, about one crash every 4 weeks counting the 7 day cycle, so about one a season, and about one every 11 days when fully invested) up to `MaxChanceMultiple` (5x) as the share of all player wealth in ordinary stocks and houses rises to `FullExposureShare` (60%). `StockService.RiskyAssetShare()` computes that share (gold and bonds count in the total only, so they never raise it) and is passed in lazily from `CommandManager.RunBackgroundTasks`. A crash rolls a severity when it starts (`CoinAccounts.CrisisSeverity`, `r*r`, so mostly moderate) and runs Decline (2 days), Bottom (1) and Recovery (4), so a whole crash fits in a season. Ordinary stocks fall from 38–50% by tier (60% crypto) at severity 0 to 70/80/90% (99% crypto) at severity 1, houses 25% to 70% (`MarketCycle.FallFor`, `PropertyFall`; the index has no limit but `PropertyCatalog.IndexFloor`). Recovery gives back `RecoveryShare` (85%) of the loss in log terms, so prices end below where they were; `StockService.TickIfDue` applies the drift each tick via `MarketCycle.DriftFor(stock, phase, severity)`; during a crash an ordinary stock is pulled (at the normal reversion rate) towards `Stock.CrisisAnchor`, its price when the crash began moved by the drift each tick, not towards its base, and `Stock.NoiseDrag` cancels the noise's own downward pull in log terms, so the typical stock falls by the stated amount and the spread stays as narrow as in normal trading (a free random walk without this took a mild crash far past its fall; `MarketCrashTests.ADecline_FallsByItsStatedAmount…` guards it; crypto just follows the drift), and once the crash ends stocks keep their new level as their base (`ResetBasePrices`). A phase saved under older lengths is cut to the current length. Headlines (including how bad it is) go to the last few active channels (`CommandManager.PostToRecentChannels`), and `.property` shows the current risk (`MarketCycle.RiskLine`: today's crash chance, how many times normal, and the exposure behind it, or the crash under way). Phase state lives on `CoinAccounts` (`MarketPhase`, `NextCrisisAllowedDay`, `CrisisSeverity`).
- `.convo` (`Models/ConvoModel.cs`, `Services/ConvoCorpusService.cs`): the scrape starts by itself once the bot is connected when nothing was ever scraped or an earlier one was cut off (every deploy restarts the bot, so a scrape that takes hours must resume: `EnsureScrapeStarted` from the minute loop, `ShouldAutoScrape`, `HasUnfinishedChannels`; a scrape that ends with channels unfinished (an error) is retried after `AutoScrapeRetry`, 10 minutes, unless an admin ran `.scrapeconvo stop`; once everything is saved only `.scrapeconvo` fetches new messages), and `.scrapeconvo` (bot admins; `status`, `stop`) runs it again. It downloads, in the background, every message the bot can read in server `ConvoCorpusService.GuildId` except channel `ExcludedChannelId` (and its threads, or a category's channels): text, news and voice chats, open threads and archived public threads. It writes them to `convo_data/messages/<channelId>.tsv` in the bot's working directory on the Pi (`id\tusername\ttext`; never in the gist or the repo), saves its place per channel in `convo_data/scrape_state.json` after every 100-message page (`PagePause` between pages), and later runs only fetch new messages. It reads the history newest first, which would make an unfinished model lean on recent chat, so it does a random sample pass first (`SampleChannels`: `SamplePages` pages of 100 messages, `FavouredSamplePages` for the favoured channels, each around a random moment between the channel's creation and now via `RandomMessageId` and `Direction.Around`, saved apart in `convo_data/samples/<channelId>.tsv`, `ChannelProgress.Sampled`), then a model reload, then the full history, rebuilding the model every `ReloadDuringScrape` (15 minutes) as it goes. `SourceFiles` picks what the model learns from: a channel whose history is all saved (`Done`) uses its full file, one still being scraped uses its random sample and NOT its newest-messages tail (its partial file only if it has no sample yet), and with no scrape state every file is read as it is. Whatever is read is then sampled uniformly over messages above `MaxMessages`. Each build fills a `ConvoCorpusService.LoadReport` (messages read vs saved, files and random samples used, oldest/newest date, share from the last 30 days and year), shown by `.scrapeconvo status` and logged. `Clean`/`Extract` drop bots, system messages, bot commands, code blocks, links and @everyone, and resolve mentions to plain names. The knobs below are the defaults of `ConvoSettings` (`Models/ConvoSettings.cs`: chaos, temperature, hook, ownstart, topicline, topicpull, favoured, minlines, maxlines, maxcopy, each with a range): `.convoset` (bot admins, `CommandManager_ConvoSettings.cs`) lists them, `.convoset chaos 0.9` (or `90%`) changes one and `.convoset reset [name]` puts them back, saved to `convo_settings.json` next to the bot (gitignored) and shared by reference with the model (`ConvoModel.Settings`, `ConvoCorpusService.Settings`), so the next `.convo` uses them with no deploy or rebuild. The Ollama settings for other servers are separate (`convo_options.json`). `ConvoModel` is a word Markov chain per person (`Chain`: entries grouped by speaker and sorted by context, so every line is built from its speaker's own messages; two words of context, one word of their own `Chaos` (85%) of the time, which makes it unhinged, and every chain pick is warmed by `ConvoModel.Temperature` (1.5: a follow-up word's weight is its count^(1/T), so rare ones come up more; 1 is as said, a sample of `WarmSample` entries on huge ranges), and a line over `MaxCopiedWords` (2) words that repeats a real message word for word is made again (`IsCopy`, a hash of every message); everyone's one-word chain only bridges a word the speaker never used, such as a seed, and people with under `MinOwnMessages` borrow it for the chaos steps), about 30 bytes a word, built in the background at startup (`EnsureLoadStarted` from the minute loop) and after each scrape from at most `MaxMessages` (a random sample above that). Messages from `FavouredChannelIds` (`ConvoMessage.Favoured`, from the file name via `IsFavoured`) make up `FavouredShare` (`ConvoModel.DefaultFavouredShare`, 95%) of every choice whenever they have one, whatever their size: each person's chains are split into two pools (`Group` = speaker and pool) and every next word, opening word and run start takes the favoured pool 95% of the time (`PickPool`, `TryPickOwn`, `RunStart`), falling back to the other pool when it has nothing. Under `MaxMessages` the favoured channels are kept whole and the rest sampled into what's left, and those channels are scraped first. A convo is 3 to 10 lines (`MinLines`/`MaxLines`) of `user: text`, posted with the speaker in bold (`ConvoModel.Format(lines, boldSpeakers: true)`, and `ConvoService.BoldSpeaker` for the LLM path; the name is escaped with `Format.Sanitize`): `.convo @someone [words]` tags one person (more than one is refused, bots are ignored) and makes a monologue of `SoloMinLines`..`SoloMaxLines` (2 to 4, settings `solomin`/`solomax`) lines that are only theirs (`Generate(random, seed, onlySpeaker)`; the tag is dropped from the topic words; refused with a message when the model has read nothing from them, matched by username ignoring case; the Ollama path in other servers ignores the tag): otherwise speakers come from a real run of messages in one channel, each line starts with a word its speaker really opens with or picks up a word from the line before that the speaker also uses (`ReplyHookChance`, `OwnStartChance`), and `.convo words` makes the words the topic (`TopicOf`: known words only, filler dropped when there's anything else): the first line and `TopicLineChance` (60%) of the rest start with how that speaker really led into a topic word (up to two words before it, `Chain.SampleLeadingTo`, else how anyone did, `SharedLeadInsTo`, scanned only when needed), and until a line mentions the topic each step takes a topic word `TopicPull` (50%) of the time when the speaker has one to follow (`TryPickFrom`). Words nobody used are ignored. In that server it only ever answers from the model, never the LLM: before the history is in, it says it's loading or reading (and starts the scrape if none is running). In other servers the old Ollama prompt (`ConvoService`) runs off the gateway task with a 60 s timeout, and only lines matching `ConvoService.KeepChatLines` (`name: text`, a name without spaces) are posted, at least 3 or it retries (`LlmConvoTries`). It's sent with no mentions allowed.
- Battle Person cards, levels and raids (Face Off was removed to make raids the main PvP). A card (`Games/Models/Cards/BattlePerson.cs`) is a face (thispersondoesnotexist, foil = holographic picture only), a funny name (`CardNamer`: `Gary "Knuckles" Pemberton`, the nickname fits the archetype), a `Rarity` (Common 60%, Rare 25%, Epic 12%, Legendary 3%) and an `Archetype`, and its strength is one number, `Power` = `CardLevels.BasePower` 20 + `CardLevels.RarityPower` (10/14/18/23) + `CardLevels.PowerPerLevel` 1.8 x level (`CardLevels.PowerOf`); a legendary is worth about 7 levels (~$37k of training), about what its 3% pull costs. Old saves load: the old stats and focus are ignored, and the saved `Ability` number is the archetype (`[JsonProperty("Ability")]`; 1 Heal became Guardian, 2 Shield Guardian, 3 Reroll Trickster, 4 CritBoost Brute, new 5 Thief, 6 Gambler). The five archetypes (`Archetypes.cs`, every number is a constant, and `ArchetypeTests` keeps them within a fair band of each other and of a trait-less card): 🥊 Brute +15% power raiding, -10% defending; 🛡️ Guardian +15% defending and 2 hours of protection after a raid gets through; 🦝 Thief wins pay 2.5x the stake instead of 2x but a failed raid costs 25% extra; 🃏 Trickster rolls one failed raid a day again; 🎰 Gambler's power swings 25% up or down on a coin flip each raid, a natural 100 doubles the loot and a natural 1 doubles the loss. Matchups: Brute beats Thief beats Guardian beats Brute (+20% power for the counter, shown in the preview and result), Trickster and Gambler have none. A card's `Level` (0 to `CardLevels.MaxLevel`, 30) and `Xp` belong to the player: `CardLevels.CarryOver` copies them to a newly kept card in `SaveCard`, and `CoinService.ClearAll` keeps every card in `CoinAccounts.CarriedCards` at level 0 and gives it back when the account is made again. XP (`CardLevels.AddXp`, `XpToNext` = 100 + 20 x level) comes from raids and from every `.cardpull` (`PullXp` 25, to your current card, kept or not); `.train` (or `.train max`) buys the rest of the next level for `FullLevelCost` ($2,000 x 1.3^level, about $17.5M for all 30) less the XP already earned, into the jackpot. `.cardpull` shows how the pulled card compares with yours at your level (`Compare`) and a Keep button. Raids (`.raid`, `Services/RaidService.cs`, numbers in `Models/RaidRules.cs`, commands and buttons in `Managers/CommandManager_Raids.cs`) resolve instantly: the chance is A^1.2/(A^1.2+D^1.2) clamped to 5-95% from the raider's power (archetype bonus, counter bonus, revenge) and the defender's (archetype, counter, stance `CoinAccount.RaidStance`: Guard 1.3, Counter 1.0, Hoard 0.8, hired guards `.guards` 1.5x for 6 hours at 2% of worth into the jackpot bookable 24 hours ahead, and the underdog penalty +20% per doubling of how much richer they are than the raider, up to +100%); a level 30 card beats a new one of the same rarity about 75% of the time. The stake is cash, at least 1% of the raider's worth and at most 10% of the target's (so the very rich can't raid the poor). A win returns the stake plus loot of 2x it (half against Hoard, at most 20% of the target's worth), taken cash first then on the target's debt like `RaffleService.Seize` (Golden Parachute limits it to cash), with 10% kept back as `CoinAccount.Bounty` on the raider; a loss gives the stake to the defender, and Counter takes it again from the raider (cash then debt). Whoever beats a player with a bounty collects it. Limits: 3 raids an hour (`RecentRaidUtcTicks`), the same target once per 6 hours (`LastRaidOnUtcTicks`), 1 hour of protection after a successful raid, a Shield power-up refuses raids, and no raids with either side's bet open. The raided player gets a `RevengeToken` for 24 hours (with the raider's `Stake`): one raid back that ignores protection, the pair cooldown and the underdog penalty and gets +25% power (a revenge raid gives no token back). A revenge raid is always allowed, whoever is richer: its stake limits are `RaidRules.RevengeStakeLimits` (at most what the raider staked; at least $1 and at most the normal minimum), not the 1% / 10% worth limits that would refuse a rich victim hitting back at a poor raider, and the loot is still capped at 20% of the target's worth. `CoinAccount.RaidStreak` counts raids won in a row (best in `Stats.BestRaidStreak`). The result is a picture (`Services/RaidRenderer.cs`: both cards' faces, names, power, a big VS and the d100 result, drawn with `PixelFont` and cached card art) plus a short text (`RaidService.Describe`, 4 to 6 lines: who, the roll with matchup tags, the money, the winner's battle cry `Archetypes.Cry` and an XP footer; the picture and embed title carry the cards and the result), pinging only the defender, with a Revenge button. `.card` is the control panel (`card` buttons: Train, Train max, Hire guards; stance menu), `.raid` alone lists revenge and bounties, `.raid @person` previews the odds with stake buttons (`raid` prefix). `RaidTests` and `ArchetypeTests` check the odds curve, that raiding equal cards against Guard is only mildly profitable, that guards, Counter and the underdog penalty make it a losing bet, that no archetype is a free lunch, and that money is conserved.

## Adding things
- **New command**: write handler in the matching `CommandManager_*.cs`, then register it in the `_commands` list in `CommandManager_Main.cs` (comment there says so).
- **New service**: create in `DiscordBot/Services/`, register in `Startup.ConfigureServices`, inject into `CommandManager` ctor if commands need it.
- **New game**: Game + Manager + Player model, register Manager singleton in `Startup`, add handler in `CommandManager_Games.cs`.

## Intentional behaviour: do not "fix" these
The owner wants these exactly as they are. Reviewers and agents must not report them as bugs, "correct" them, add patch notes about changing them, or write text that says otherwise. `MoneyTests` pins the first two, and `PatchNotes.Retired` lists the patch notes for undoing them so they are never announced.
- **The $1,000 "daily" handout is paid to every account every hour** (`CoinService.HourlyIncome`, in `AddInterest`), not once a day, and not only to active players.
- **Donations can pay the donor back 6x, 1 in 12 times** (`CommandManager.DonationBonusOdds`/`DonationBonusMultiple`), even though two friends can pass money back and forth with it. Donating counts as money activity for the raffle.
- **Blackjack and duck race lobbies are global**: one open lobby across all channels and servers, started by hand (Start button or `.bj start`), with no auto-start timer.

## Conventions / gotchas
- **Game time is fast.** A season (a `.clear coin` market and accounts) lasts 2 to 4 weeks, and the economy runs in hours (a house's rent 0.7% an hour, interest 2% an hour, debt 10% an hour, stock ticks every 5 minutes). Anything slow must be scaled to that, not to the real world: crash cycles last days, property swings days, bond yield and holding costs are hourly, options run 15 minutes to 3 days and are priced by simulating the game's own tick process. Don't use real-world yearly rates or month-long cycles.
- Files use UTF-8 BOM and namespaces matching folders (note: `DiscordBot.Exceptions` namespace is used for exceptions that live in `Common/Exceptions`).
- Hardcoded admin/bot IDs live in `CommandManager_Main.cs` (`_adminIds`, `_botId`); blacklists in `appsettings.json` (`AppSettings.cs`).
- Discord message limit 2000 chars (`_messageCharLimit`); keep replies under it. Embeds are capped at 6000 chars total and 1024 per field, so long lists go through `TextPaginator.Paginate` (`Common/Helpers/TextPaginator.cs`) and send one embed per message, as `.help` does.
- `mappings.json` / `reminders.json` are runtime data copied to output.
- Patch notes: a significant change gets a one-line entry at the top of `PatchNotes.All` (`Models/PatchNotes.cs`); `.patchnotes` shows them.
- Branch `gambling-rework` is active; `master` is the deploy branch.
